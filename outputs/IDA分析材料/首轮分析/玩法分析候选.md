# 占城大师：IDA 首轮玩法验证候选

本次只读扫描现存 GameModule 方法索引、dump.cs 和 script.json；未启动 IDA、MuMu 或游戏。dump.cs 的方法体为空，本文的优先级只基于方法签名、字段布局、异步标记和名称；任何调用边、公式、实际字段读写和“可移植”结论都需要 IDA 正文验证。

来源根目录：`outputs/IDA分析材料`。完整 C ABI 签名、RVA、dump.cs 声明行与 script.json 记录起始行见 `priority-and-chain-methods.tsv/json`。所有 RVA 沿用 arm64 导出。它们不是原始文件偏移；IDA 里须核对映像基址和装载方式。

## 六个优先方法

### 1. 六边形纯坐标验证

- 精确名：`HexManager$$HexDistance`
- RVA：`0x3d2a600`；dump.cs：5446；script.json：5085。
- C#：`public static int HexDistance(HexManager.HexCoord a, HexManager.HexCoord b) { }`
- 字段候选：HexCoord.q int @0x0 (dump 5130); r int @0x4 (5131)
- 理由与边界：只有两个值类型HexCoord输入、int输出，适合首先检查结构传参和标量反编译；不能在看正文前假定距离公式。

### 2. 兵力名额

- 精确名：`GameModule.BattleGameSceneManager$$GetAvailableSlots`
- RVA：`0x3ded9ac`；dump.cs：37402；script.json：30603。
- C#：`public int GetAvailableSlots(bool isEnemy) { }`
- 字段候选：_playerRoleCount int @0x200 (37305); _enemyRoleCount @0x204 (37306); MAX_ROLE_COUNT=100 (37307); _playerReservedCount @0x208 (37308); _enemyReservedCount @0x20C (37309)
- 理由与边界：可先厘清当前兵数、预留名额与上限的关系，再追异步生成兵堆；不要把常量100直接当作已经确认的最终公式。

### 3. 战斗标量规则

- 精确名：`GameModule.SynergyEffectManager$$InternalCalculateDamage`
- RVA：`0x3e0f6f0`；dump.cs：38731；script.json：32265。
- C#：`private int InternalCalculateDamage(int originalAttack, bool isEnemy, int fetterCount, int requiredCount) { }`
- 字段候选：IsUseNewFetter bool @0x20 (38713)
- 理由与边界：int/bool输入与int返回、无异步标记，适合确认条件分支、取整与羁绊阈值。IsUseNewFetter是否真的读取仍需IDA。

### 4. 对局金币状态更新

- 精确名：`GameModule.BattleGameManager$$ChangeCoin`
- RVA：`0x3de3cf4`；dump.cs：36737；script.json：30111。
- C#：`public void ChangeCoin(int coinNum) { }`
- 字段候选：hasCoin int @0x28 (36602); battleInitCoin @0x2C (36603); battleTotalEarned @0x30 (36604); battleTotalCost @0x34 (36605)
- 理由与边界：只有金币增量参数；先确认余额/总收入/总支出的写入及事件副作用，再接开格操作。UI事件可能需要替身。

### 5. 六边形归属判定

- 精确名：`GameModule.HexBehaviour$$DetermineHexCamp`
- RVA：`0x44298ec`；dump.cs：25163；script.json：18141。
- C#：`private void DetermineHexCamp() { }`
- 字段候选：isEnemyHex bool @0xA0 (24796); isOpened bool @0xA1 (24797); _roleEnemyList @0x1D8 (24848); _rolePlayerList @0x1E0 (24849)
- 理由与边界：方法名、双方角色列表和归属字段构成占领规则的直接候选。需要查明它是否只判定归属、是否触发异步Encroachment/表现事件。

### 6. 开格到兵堆的集成入口

- 精确名：`GameModule.HexBehaviour$$OpenHex`
- RVA：`0x4424d5c`；dump.cs：25015；script.json：17877。
- C#：`public void OpenHex(bool isEnemy, bool isHard = False) { }`
- 字段候选：canOpen bool @0x50 (24782); price int @0x9C (24795); isEnemyHex @0xA0 (24796); isOpened @0xA1 (24797); soilderObj GameObject[] @0x1C8 (24839)
- 理由与边界：优先级最后：它用于把前述规则接到一次玩家操作，可能连接UI/动画/资源与异步生成，因此不应先整类搬移。

## 最小验证路线与入口

建议先验证 `HexDistance → GetAvailableSlots → InternalCalculateDamage → ChangeCoin` 四个数值/状态方法，再验证 `DetermineHexCamp → OpenHex` 两个状态入口。这里的箭头表示分析顺序，不是已经证实的原程序调用链。

准备 Editor 验证夹具时可先使用几个合成六边形、两侧角色列表、固定配置和资源替身。原游戏是否容许绕过完整启动、各管理器的最小初始化条件，尚未确认。不要直接把空 dump.cs 编译进工程当作实现。

应用层生命周期候选为 `CoreModule.GameLauncher.Awake/Start`；尚未检查原始场景绑定，不能仅凭名称证明哪个场景实例实际调用。Start、GameLogic、InitGame 是异步包装，关键逻辑在对应 `MoveNext`。入口中另有 Login、管理器初始化和加载完成事件，依赖范围明显大于单个玩法规则。

游戏开始可沿 `GameManager.StartCoreGame`、`CoreGameManager.StartGame`、`BattleGameManager.StartGame(BattleContext)`、`BattleGameSceneManager.StartGame(GameType)` 设置检查点；是否依次相互调用须查交叉引用。BattleContext 在 dump.cs 38075 起声明，含 GameType@0x40、enemyDataCofig@0x18、奖励及结束回调。

地图候选为 `GenerateHexBehaviour.Generate/InitMap` 的 MoveNext（异步资源/生成流程），然后看 `GetAllPos`、`SetHexNear` 和 `HexManager.Initialize`。GenerateHexBehaviour 在 dump.cs 23963 起的类型块声明有 hexSize@0x20、mapMapSizeX@0x28、mapMapSizeZ@0x2C、HexBehaviours@0x30、hexPrefab@0x48、hexEnemyPrefab@0x50、_currentConfig@0xE8；因此整个 Generate 并非纯算法。

六边形有六个邻居字段（0x68/0x70/0x78/0x80/0x88/0x90）、坐标 q/r 和双方角色列表。开格先查 `NearHasOpen`/`CheckCanOpen`，再查 `OpenHex`；兵堆入口看 `SetHexSoldierPile` 与 `<CreatSoldierPile>d__132.MoveNext`，不能只看 CreatSoldierPile 的短异步包装。占领入口看 `DetermineHexCamp` 以及两个 Encroachment 的 MoveNext。

补充战斗入口：EntityBase.Wound 为 abstract，RVA=-1，不存在这个抽象声明本身的实现；实际角色入口为 RoleBehaviour.Wound（0x3D86A44）。若先看较小规则，可看 ApplyBuildingDamageMultiplierIfNeeded（0x3D8CC9C）。对局金币和长期背包资源是不同类型：UserResourcesManager.GetResourceCount 返回int，但 UserAssetData 声明含 BigInteger 字段，转换/缺省值需要正文核实。

## 覆盖限制

GameModule-方法索引.tsv 共有 6089 行方法记录；它不含无 namespace 的 HexManager 或 CoreModule.GameLauncher。已从 script.json 的 396253 个 ScriptMethod 记录中补全这些入口，并按 RVA 与 dump.cs 对齐。多个重载可能具有相同 Name，实际分析应使用 Name+RVA+Signature 三项共同定位。

“兵堆”是 HexBehaviour 的 soilderObj / CreatSoldierPile 线索，不应在未看实现前等同于单个兵营连续产兵；BarracksArchitectureBehaviour 是另一条生成链。所有关联字段只是候选，并没有声称某个方法已经证实访问它们。
