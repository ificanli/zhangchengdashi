## 1. HexDistance：参数与整数语义

原型：`int HexDistance(HexCoord a, HexCoord b)`，IL2CPP 原生原型末尾另有 `const MethodInfo*`。`HexCoord` 为两个 int32 组成的 8 字节值类型。

汇编 `0x3D2A620..0x3D2A62C` 把 x0/x1 的低 32 位及右移 32 位后的低位分开使用，确认：a.q/a.r 均来自 x0，b.q/b.r 均来自 x1。没有坐标指针解引用。

`0x3D2A658..0x3D2A67C` 为全部 W 寄存器运算：

- dq = a.q - b.q；dr = a.r - b.r；ds = a.r + a.q - b.q - b.r。
- 以 `SUBS` 后 `CNEG ..., MI` 对三个结果取绝对值。`MI` 测试回绕结果的符号位，并不检测整数溢出。
- 三个绝对值相加仍为 32 位 `ADD`。
- `0x3D2A68C..0x3D2A694` 是负值先加 1 再算术右移，等价于有符号整数除 2、向零截断。直接 `sum >> 1` 对负奇数不等价。

可恢复的 C# 算术模型：

```csharp
static int AbsWrap32(int value) => value < 0 ? unchecked(-value) : value;

static int HexDistance(HexCoord a, HexCoord b)
{
    unchecked
    {
        int dq = a.q - b.q;
        int ds = a.r + a.q - b.q - b.r;
        int dr = a.r - b.r;
        return (AbsWrap32(dr) + AbsWrap32(dq) + AbsWrap32(ds)) / 2;
    }
}
```

不能将 `AbsWrap32` 无条件换成 C# `Math.Abs(int)`：`Math.Abs(int.MinValue)` 抛 OverflowException，而此处 CNEG 对 0x80000000 仍得到 0x80000000，没有该异常分支。用 long 防溢出会改变原二进制极值行为。常规地图坐标范围内，上式就是轴向六边形距离公式。

序言中的 `off_8CEA738` 已由 script.json 2559102–2559104 行核实为 `System.Math_TypeInfo`，不是玩法配置。元数据初始化/类型初始化由两个原生 helper 完成。纯算法提取可以去掉 IL2CPP 初始化序言，但这不等于原入口没有运行时依赖。

## 2. InternalCalculateDamage：没有阵营或 AB 读取

原型：`int InternalCalculateDamage(int originalAttack, bool isEnemy, int fetterCount, int requiredCount)`。

`0x3E0F6F0` 比较 W3/W4，`B.LT` 是有符号比较。未达阈值直接返回 W1。达阈值后：

1. `SCVTF S0, W0`：有符号 int 转单精度浮点。
2. `FMUL S0, S0, S1`，S1 为 0.5：单精度乘半。
3. `FCVTZS W8, S0`：向零截断转有符号 int。
4. `ADD W0, W8, W0`：与原始攻击相加，32 位回绕。

函数没有内存读取或调用，x0（self）、w2（isEnemy）、x5（method）均不参与计算；此前类型中的 `IsUseNewFetter` 只是字段候选，在这个方法内未被读取。不能据此推断它的调用者也没有 AB/阵营差异。

可恢复为：

```csharp
static int CalculateDamage(int originalAttack, int fetterCount, int requiredCount)
{
    if (fetterCount < requiredCount)
        return originalAttack;
    float half = (float)originalAttack * 0.5f;
    return unchecked(originalAttack + (int)half);
}
```

注意：这与 `originalAttack + originalAttack / 2` 在大整数上不总相同，也不能改成 `(int)(originalAttack * 1.5f)`。例如默认正常浮点舍入下，16,777,219 先转 float32 成 16,777,220，半值 8,388,610，最终得到 25,165,829；整数除半方案会得到 25,165,828。负数的 FCVTZS 是向零，不是 floor。

伪 C 中 `if (v7 == INFINITY)` 确实来自 `FCMP` 与 `CSEL`，不是反编译凭空生成。然而对本函数 int32 输入，转 float32 再乘 0.5 的范围为 [-2^30, 2^30]，既不会无穷也不会 NaN，所以该保护对合法签名输入不可达。int32 加法仍可能溢出：int.MaxValue 达阈值时回绕为 -1,073,741,825。若设计决定钳制负数/溢出，那是行为改动，不是等价恢复。

上述 C# 等价性按通常 float32 舍入环境分析；没有检查进程是否修改 FPCR。也没有编译或运行 C# 恢复实现。

## 3. GetAvailableSlots：AB 关闭为“不限额”哨兵

该方法 `.c` 首行有 `local variable allocation has failed` 警告。其末尾算术可由汇编独立确认，但初始化/调用参数不能照搬伪 C。

`0x3DEDA0C` 只向 x0 加载泛型 MethodInfo 地址，随后 `BL get_Instance`。伪 C 中额外列出的 `isEnemy, method` 不是已证实的有效参数。原导出签名只有一个 `const MethodInfo_5FBEB64*`。script.json 2679584 行将该指针辨认为 `Method$QuickTutor.Singleton<ABTestManager>.get_Instance()`。

`0x3DEDA18` 把 x1 置零后调用 `ABTestManager.get_GamePlayImprove01IsBTest`；`0x3DEDA20` 检查返回值最低位：

- false：`0x3DEDA5C` 直接返回 `0x7FFFFFFF`，即 int.MaxValue。
- true：根据保存的 isEnemy 最低位选取计数。玩家字段为对象+0x200 和 +0x208，敌方为 +0x204 和 +0x20C。
- `ADD W8` 得 current+reserved；`SUB W8` 得 100-used；`BIC W0,W8,W8,ASR#31` 把负结果归零，非负保持。

纯规则提取：

```csharp
static int AvailableSlots(bool useLimit, int roleCount, int reservedCount)
{
    if (!useLimit)
        return int.MaxValue;
    int remaining = unchecked(100 - unchecked(roleCount + reservedCount));
    return remaining < 0 ? 0 : remaining;
}
```

实际 AB 标志来源与默认值不在本方法中。不能总返回 `Max(0,100-used)`，也不能把 int.MaxValue解释为实际可生成这么多兵。代码没有上界钳制，若计数为负或发生溢出，结果可能超过 100；从数据约束上防御这些情况是额外行为修改。

Null 路径：`0x3DEDA14 CBZ x0` 进入 `0x3DEDA70 BL unk_3C3D4CC`。JUMPOUT 指向 0x3DEDA74（本函数 end），不是正常返回一个名额的分支。null guard 与 helper 调用已证实；helper 本体未独立分析，具体异常类型仍以运行时符号/正文核实为准，不能把 JUMPOUT 自动翻译为 return 0。

## 4. DetermineHexCamp：只决策，不直接修改归属

`0x4429918` 从对象+0xA1读 isOpened；为真立即返回。随后读取 +0x1E0 的玩家列表以及 +0x1D8 的敌方列表，各自 +0x18 的 int32。

原导出 il2cpp.h 700746–700750、700796–700800 行确认 List<RoleBehaviour> 的 `_size` 位于对象+0x18（对象头16字节，_items指针8字节，然后_size）。因此这里确实检查列表 Count，不是从角色血量/战力求和。未遍历成员，未剔除空/死亡成员；这些列表的维护不在本方法中。

在合法 List.Count 非负且列表非 null 的条件下：

| isOpened | 玩家数量 | 敌方数量 | isEnemyHex | 动作 |
|---|---:|---:|---|---|
| true | 任意 | 任意 | 任意 | 无 |
| false | >0 | >0 | 任意 | 无（双方同时存在） |
| false | 0 | 0 | 任意 | 无 |
| false | >0 | 0 | true | 尾调用 EncroachmentEnemy，地址 0x4428468 |
| false | 0 | >0 | false | 尾调用 EncroachmentPlayer，地址 0x4428CD0 |
| false | 单方存在 | 另一方0 | 已属该单方 | 无 |

方法名中的 Enemy/Player 在上述分支中对应被侵占的一方，不能反过来写成新归属。尾调用位置分别为 0x4429968 / 0x44299A8。此函数自身没有写 isEnemyHex/isOpened，也没有等待动作完成。

可提取纯决策：

```csharp
// 此返回值只代表需要触发的动作，不证明动作已完成。
if (isOpened) return None;
if (playerCount > 0 && enemyCount == 0 && isEnemyHex)
    return EncroachEnemyHex;
if (enemyCount > 0 && playerCount == 0 && !isEnemyHex)
    return EncroachPlayerHex;
return None;
```

此简化以正常 List.Count 非负为前提；对损坏的负_size，汇编还有不同有符号路径，不应宣称简化对任意内存比特都等价。列表 null 进入 0x44299AC 的 `unk_3C3D4CC`；不能擅自当作空列表。`isOpened=true` 的早退发生在列表读取前。

原型仍带隐藏 MethodInfo*，但尾调用前没有重新显式构造 x1。参数可能被优化器视为未使用；不要从伪 C 打印 `method` 就断言被调方法读取了它，更不要复制该寄存器状态来做跨运行时调用。C#恢复应调用对应托管方法/显式效果接口。
