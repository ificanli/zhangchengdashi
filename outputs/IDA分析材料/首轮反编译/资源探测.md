# 占城大师 APK 资源可读性抽样探测

探测对象：`work/apk-intake/zhancheng-dashi-1.04.apk`。工具为从 PyPI 安装的 UnityPy 1.25.4，使用独立的 `work/asset-probe/.venv`。只单独加载了下表三个 ZIP 条目；没有整包载入、启动游戏、启动 Unity、修改 MuMu/IDA 或用户工程，也没有上传包体。

## 结果

| APK 条目 | 大小 | 解析结果 |
|---|---:|---|
| `assets/bin/Data/data.unity3d` | 3,801,403 字节 | 成功识别 6 个 Unity 2022.3.62f3 序列化文件，共 9,266 个对象 |
| `assets/aa/catalog.bundle` | 196,973 字节 | 成功识别 1 个 AssetBundle 和 1 个 TextAsset，目录 JSON 可读 |
| `assets/aa/Android/91aca73acb86d6607f0efa1f803348be.bundle` | 19,576 字节 | 成功识别 1 个 AssetBundle 和 2 个 Shader；该包保留 TypeTree |

`data.unity3d` 包括 `globalgamemanagers`、`unity_builtin_extra`、`globalgamemanagers.assets`、`sharedassets0.assets`、`level0`、`resources.assets`。对象清单包括 1,078 个 GameObject、4,146 个 MonoScript、1,631 个 MonoBehaviour、140 个 TextAsset、116 个 Texture2D、51 个 Sprite。MonoScript 对应 73 个程序集名称、3,703 个不同的程序集/命名空间/类名组合。这些是序列化类型引用，不是恢复出的 C# 源文件或方法实现。

## 场景与启动依赖

BuildSettings 的场景列表只有：

`Assets/GameRes/BundleRes/Scene/MineGameMain.unity`

对应 `level0` 内有 46 个 GameObject 和 73 个 MonoBehaviour。名为 `Main` 的对象挂接了：

- `GameFramework.Base.GameStartEntry`，程序集 `GFRunning.dll`
- `ljzs_lt.GameStart`，程序集 `Assembly-CSharp`
- `CommonGameModule.Login.LoginTest`，程序集 `Assembly-CSharp`
- `L_Tools.ServerMgr`，程序集 `Assembly-CSharp`

场景中还存在 `LoadingPanel`、`UICanvas`、`UICamera`、`ProgressText`、`BGSpine`、`Logo`、`EventSystem`，以及调试工具对象。依赖类型可见 URP、UGUI、TextMeshPro、Spine、GFHanldMono 和 DebugSystem。它们说明启动场景的资产与组件身份有可读证据；没有验证这些组件在 Editor 的执行行为。

Addressables catalog 为标准 JSON，`m_LocatorId` 是 `AddressablesMainContentCatalog`，含 3,705 个 internal ID，其中另有场景：

`Assets/_Scene/Game.unity`

catalog 引用的 19 个本地 Android bundle 文件均存在于 APK 清单；本次仅解析其中最小的 Shader 包。没有验证另外 18 个 bundle 的对象内容、跨包引用或场景是否完整可恢复。

## 文本资产与热更新 DLL 探测

共检查 141 个 TextAsset（主数据包 140 个 + catalog 1 个），逐项保存原始字节并验证 SHA-256 与清单一致。

- 没有 TextAsset 以 PE/DLL 的 `MZ` 签名开头。
- 没有发现解码后的 base64 或 base64+gzip 载荷以 `MZ` 开头。
- 122 个 TextAsset 是可解开的 base64+gzip JSON 数据表。
- TextAsset 名称以及 catalog internal ID 中没有发现 `.dll`、`.cs`、`.lua`、HotFix、HotUpdate、ILRuntime、HybridCLR 线索。
- 另有 `AddressablesConfig`、Spine 数据、语言与配置内容；本次没有在其中恢复出可执行的托管程序集。

这个结果只适用于已检查样本，不能排除其他 bundle、native 库或自定义加密载荷内另有代码。

## 解析限制

主数据包的 6 个序列化文件均未保留 TypeTree。UnityPy 能用内置定义读取 GameObject、MonoScript、TextAsset 和设置对象，并读取 MonoBehaviour 的通用头部，但对 1,526 / 1,631 个 MonoBehaviour 严格读取时出现长度不匹配，例如 `Expected to read 216 bytes, but only read 48 bytes`。这些错误在 `probe.json` 的 `strict_read_error` / `type_tree_error` 中保留。

本次为取得组件身份，对这些 MonoBehaviour 使用了仅供探测的 `read(check_read=False)` 读取通用头；这不代表已恢复自定义字段、序列化布局或方法实现。其余头部读取长度匹配的组件也不因此证明代码可执行。

Unity 内部 PlayerSettings 显示 `companyName=cszdz`、`productName=zijie`、`bundleVersion=2.17.1`。这是包内 Unity 元数据，和 APK 文件名中的 `1.04` 是不同口径，应由主任务结合 Android manifest 确认版本身份。

## 可复用中间文件

- `probe.py`：三个样本的逐项解析脚本。
- `probe.json`：完整对象计数、MonoScript 清单、MonoBehaviour 通用头、读取错误与 TextAsset 哈希。
- `summarize_probe.py`：启动组件关联、文本编码及 catalog 检查脚本。
- `summary.json`：场景路径、启动组件、程序集计数、文本检查、catalog 路径等结构化摘要。
- `textassets/`：抽样读取的 TextAsset 原始字节。以序列化文件和 PathID 区分重名资产；以 `probe.json` 的 `saved_to` 为准。

结论：抽样资源是可解析的 Unity 序列化资源，启动场景与业务类型引用能够识别；目前证据支持继续进行资产导出和 IL2CPP 类型/字段还原尝试，不支持“已经恢复出可运行 Unity Editor 工程”的结论。
