## 1. 为什么要恢复三套不同底座

第 15 阶段的真实 GameLauncher.Awake 在发起基础初始化任务后调用 CheatControl.Instance.Init；元数据确认 CheatControl 继承 `L_Tools.Singleton<CheatControl>`。GameLogic 的 ABTestManager 则继承 `QuickTutor.Singleton<ABTestManager>`。两者先前 getter 都是 `(T)null`，字段初始化器丢失。第 13 阶段恢复的 ToolModule.ManagerBase 无法替代这两个普通 C# 泛型底座。

CustomBundlesManager 又不同：它是 `I2.Loc.RegisterBundlesManager` 派生的 Unity 组件，有自己的静态 `_instance`。其 Instance getter 为空会阻断 InitManager 的真实资源等待。这三个问题必须在原类内分别恢复。

## 3. L_Tools.Singleton<T> 的恢复

恢复为原嵌套 readonly 字段初始化器及 getter：

```csharp
private class SingletonCreator
{
    internal static readonly T instance = new T();
}

public static T Instance => SingletonCreator.instance;
```

实际文件保留原属性和构造的完整元数据标注；上面仅为语义摘录。原约束仍为 `where T : new()`，没有添加 class、MonoBehaviour 或其他限制。

C# 的泛型 `new T()` 编译为 `Activator.CreateInstance<T>()`，与原生调用一致。嵌套静态字段属于每个闭合泛型类型：不同 T 各自实例化，重复读取和并发读取均返回同一对象。没有 Unity Find/AddComponent、手写锁、Init 调用或对象挂接行为。

如果 T 的构造抛错，静态类型初始化失败并缓存错误，不重试。没有捕获并返回 null，也没有把构造改成绕过构造器的分配。

## 4. QuickTutor.Singleton<T> 的恢复

恢复原字段与 getter：

```csharp
private static readonly Lazy<T> instance = new Lazy<T>(() => new T());
public static T Instance => instance.Value;
```

原 Lazy 构造签名只有 Func<T>，没有显式 LazyThreadSafetyMode 或 bool 参数，所以保留此重载的默认线程安全与异常缓存语义。factory 中使用泛型 new，与原 Activator.CreateInstance<T>() 一致。

Lazy 对象本身通过静态字段初始化建立；T 的构造发生在第一次 Value 访问。没有提前执行 factory，也没有在 getter 每次创建 Lazy。构造失败时，Lazy 保留 factory 抛出的异常，不再次调用构造函数。

原元数据中 QuickTutor.Singleton、L_Tools.Singleton 与嵌套 SingletonCreator 都含 **BeforeFieldInit**。本批使用字段初始化器，让编译器生成相同类型标志；没有添加会移除该标志的显式 static constructor。readonly 字段保留。

## 5. CustomBundlesManager 的 Unity 单例恢复

原字段 `_instance` 保留，getter 的顺序为：

1. 对 `_instance` 使用 `UnityEngine.Object.op_Equality(_instance, null)`。
2. 需要创建时，`new GameObject("CustomBundlesManager")`。
3. `AddComponent<CustomBundlesManager>()`，结果保存到原 `_instance`。
4. `Object.DontDestroyOnLoad(_instance.gameObject)`。
5. 返回 `_instance`。

名字字符串来源为原 `ScriptString 0x8D5D690`，组件泛型 MethodInfo 为 `0x8D2D2D8`。没有 FindObjectOfType，也没有挂到 GameLauncher 下；不能把第 13 阶段的其他管理器单例模板复制到这里。

保留 Unity 对象的空值比较，已销毁对象也会进入新建路径。赋值发生在 DontDestroyOnLoad 之前，遵循原异常和副作用顺序。没有增加“失败就清空字段”、异常吞掉或自动重试逻辑。

原构造只有基类调用；现有 C# 空构造隐式调用同一个基类，因此不改构造正文。原构造没有 Dictionary 初始化证据，故没有给 `_objectsDict` 添加猜测初始化，也没有把预载标志置为 true。
