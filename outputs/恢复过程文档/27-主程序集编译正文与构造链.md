本轮修改194个现有C#文件：119个文件中226个确定导出占位body改为显式缺失诊断；75个文件恢复原构造链，其中67个本地转发构造完整恢复、8个构造仅恢复base参数并保留正文缺口。**226个诊断与8个缺正文构造均计0；67个完整仅指本地构造，不表示天赋、祝福、子游戏buff、解锁规则或原玩法算法已经恢复。**

## 3. 226个确定占位body，保持未恢复状态可见

CS0171并不授权为struct构造随意填零，CS0177也不授权给out参数批量填默认值。本轮沿用严格Roslyn工具，只接受：

- 空body。
- 单条return default/null，或default(T)。
- 纯cast/parenthesized/unchecked包装的null。
- 精确的ref-null指针解引用占位形状。

除上述占位形状外的真实非空body不改。目标替换为带原类型、方法、Token及RVA位置的NotImplementedException，运行时仍能明确指出缺失实现；没有伪造成功结果。

首批在118个文件处理223个body。随后RVO2/KdTree两个返回指针的方法仍报CS0037，其原表达分别为：

```csharp
return (Agent*)unchecked((nint)null);
return (ObstacleTreeNode*)unchecked((nint)null);
```

这两项是带导出IL注释的纯null转换占位。本轮只扩展AST白名单，递归识别cast、unchecked和括号下最终仍为null的表达；不接受运算、调用或其他真实逻辑。两项明确缺失，计0。

加上独立授权的DicSingleton一项，共226个body，涉及119个去重文件。分批使用不同备份根，防止后续阶段覆盖前一阶段证据。独立Roslyn逐项证实226项都来自白名单形状；3373次其他body文本对比保持不变，擦除body后的声明/属性等价。这里的3373是分阶段对比次数，不是额外恢复的方法数。

### 4.1 天赋：36个纯转发，3个仍有额外初始化

36个天赋构造的完整汇编只有两条指令：X3清零，再B到TalentBase原构造。业务参数仍位于X1、W2、S0，对应talentId、eventType、float value。X3是IL2CPP隐藏MethodInfo，因此恢复为原三业务参数`base(talentId, eventType, value)`，没有增加第四个0或丢掉float值。

其余3项具有base前的集合初始化，不纳入完整恢复：

| 构造 | 原Token / RVA | 剩余原工作 |
| --- | --- | --- |
| HanRenCiGuTalent | 0x060010B1 / 0x3DA2FA8 | 3个实例集合创建 |
| HouQinZhiYuanTalent | 0x060010B6 / 0x3DA3684 | 实例List创建 |
| YingWuZheHaoZhaoTalent | 0x060010DD / 0x3DA6BF8 | 实例Dictionary创建 |

三项只恢复原base参数，剩余body明确throw，完整实现计0。伪代码的局部变量分配提示保留，实参顺序按原ARM64寄存器和调用目标核对，不根据不可靠的局部变量命名猜测。

### 4.2 祝福：10个native完整内联base

BlessBase原构造`0x4383F0C`调用Object构造，随后把blessId写入继承字段0x10、float value写入0x18。

10个派生祝福构造把这一原基构造完整内联。独立核验去除指令地址后，10份完整汇编都与原BlessBase构造逐字一致，因此恢复`base(blessId, value)`，没有遗漏派生工作；本地构造计10个完整。

这只是本地构造转发关系恢复。当前源中BlessBase自身的原字段赋值/业务行为仍需独立恢复，不能仅据派生类可编译就声称祝福已生效。
