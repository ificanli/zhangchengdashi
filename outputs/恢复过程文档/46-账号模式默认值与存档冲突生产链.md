# 46｜账号模式默认值与存档冲突生产链

本阶段已恢复原 ILoginProcedure 的账号模式 getter、setter 和遗漏静态构造器。**原 None=10 确实是实际默认值**，不需要用 Editor 登录 provider 或写入登录成功状态来开放原本地保存模式。

生产范围严格限定为 `Assets/Scripts/GFRunning/GameFramework/Login/ILoginProcedure.cs` 的这 3 个原方法。文件已落盘并冻结，meta／GUID 不变；16 个非目标成员逐字不变。没有修改 SDK／服务器登录标志、原冲突完成标志、45 的 DataManager 或 42 的 Fsm／Procedure。

独立 GFRunning C# 编译 exitCode=0、errors=0。直接载入并反射该次 **真实 Unity 编译参数输出的 GFRunning.check.dll**，55 项边界与 IL 检查全部通过。该测试是独立 CLR 进程内的字段与 IL 验证，没有调用 Unity 引擎方法，也没有操作用户已经打开的 GUI Unity 进程3808。

原相邻 static bool 位于 offset4，FieldToken `0x0400200A`。原 cctor 没有写这个字段；恢复也不写它。同文件实例字段、IsLoginInvalid 访问器及其余登录接口保持原样，没有借本轮恢复一并修成成功结果。

由于原显式字段已经保留在导出源码中，恢复直接读写该字段，没有另外创建 auto-property backing field。新增静态构造器保留原 Token／RVA 身份，写 `AccountType.None`，与原 native 常量10一致。

原枚举值为：

| TryGame | 1 |
| OnlyLogin | 2 |

原 setter 不会把未知整数归一化为 None，也不会验证 Enum.IsDefined。测试因此覆盖了所有列出值以及 int.MinValue、-1、0、12345、int.MaxValue，确认原 int32 原样往返。

## 对38存储门的实际作用

38 保留了原本地保存条件：模型 local-enable、Pool.CanSaveLocalData、accountType>=10，以及上层的 CanSave／LoadingManager.EnterHome。此前占位 getter 恒返 default(int)=0，并不等于原 None=10，因此错误地继续挡住原本地保存模式。

本轮恢复原默认生产者和原字段访问后，该门重新读取真实账号模式。没有把它强制设为 Tourist／Account／ProxyLogin；没有调用 SDK 登录；没有生成服务器返回值。真实运行中后续原 setter 写入的模式也会被保留，TryGame／OnlyLogin 等原禁止保存分支仍由原数值条件控制。

这仅解决账号模式访问与默认初始化，不能宣称完整登录或服务器存档闭环。Editor LocalEditorStore 仍是38中明确标记的平台 I/O 适配，非 Editor 原存储闭包仍保留显式诊断。

## 45冲突门与只读追踪

已读取 `stage45-handoff.json`，并实读 DataManager 源 SHA256 为 `C13AC70DEB97FEE2A199CF3576B06FB2362CAD9B217B3C1D298C034B292029A4`，与45稳定交付一致。本阶段没有修改它。

原静态字段为：

- SaveConflictCheckFinish：FieldToken0x040062B8、static offset0。
- HasCheckedSaveConflict：FieldToken0x040062B9、static offset1。
- ComflictStatus：FieldToken0x040062BA、static offset4。

原 ChooseConflict Token `0x06005730` / RVA `0x434D56C` 的 native 只做两次写入：先在 offset4 写入传入选择，再在 offset0 写 Finish=true。这与45恢复源码一致。该方法只是消费一个已经形成的决定；它本身不能证明服务器检查或用户选择已经完成。

原 ComflictStatus 枚举 Local=0、Server=1、Compare=2。45 的 LoadData 仍在原位置等待 SaveConflictCheckFinish。本阶段没有直接写该标志，也没有为了通过等待而调用 ChooseConflict。

已请求 getter／setter／cctor／ChooseConflict 的方法 incoming xrefs，并请求 ILoginProcedure 与 DataManager 两个 TypeInfo 全局引用。当前 IDA 已知方法直接 xref 均为空；全局引用命中原字段访问、保存读取门、ChooseConflict 与 LoadData 轮询。**这不能证明没有原赋值生产者或 inline 写入**，当前数据库的已分析引用范围仍有限。

随后主任务完成了只读9项冲突生产候选的 native 导出：DataCompareMgr 的 Awake、两份 StartCompare、OnLTCompareFinish、OnUseChoose、CompareData wrapper／MoveNext，以及 SaveConflictCanvas.OnChoice 与确认闭包。它们显示多处直接 inline 写 Finish，因此不能只找对 ChooseConflict 的调用。具体边界为：

| 原入口／业务位置 | 原 RVA | 真实前置条件与结果 |
| --- | --- | --- |
| DataCompareMgr.Awake | 0x43496B8 | 重复实例销毁；首次实例保留并登记 GameDataVersionMgr.onManualHandleData 的真实 StartCompare 回调，不直接 Finish |
| StartCompare(handler) | 0x434985C | 要求 LoginControl.I 非 null；原 IsProxyLogin 已成立时直接 Finish=true、返回 false；否则保存 handler 并进入 StartCompare() |
| StartCompare() | 0x4349900 | 用实际 LTPlayerPrefsDataManager 的 DataKey 发 RequestGameDataOnly，原超时5秒；没有“缺SDK就自动成功”分支 |
| OnLTCompareFinish | 0x434A288 | 读取真实 LoginControl／useInfo／lastUID／IsNewDevice 与 VersionConflict；无需交互时调用 local1 或 server2 的原数据处理回调后 Finish，需要比较时进入 CompareData |
| CompareData.MoveNext | 0x434C168 | 首先 await WaitForEndOfFrame；读取实际 LTPlayerPrefs 本地字符串并执行原 UID 检查；local／server决定后回调并 Finish；仍需比较时置原 LoginSynData.Compareing 并请求服务器数据，保持未完成 |
| OnUseChoose(bool) | 0x434BEAC | 消费实际 local／server选择，调用可空的原数据处理回调，然后清 Compareing、置 Finish；它不是离线能力检测 |
| Canvas.OnChoice | 0x434C864 | 打开确认面板、设置可选确认文本、绑定实际确认按钮，不立即消费选择 |
| 原确认闭包 | 0x434CAA4 | 按捕获的 bool 调用可空按钮回调，再隐藏 Canvas；只有回调存在才传递选择 |

原 ManualHandleDataDelegate 的值域是 GameDataUseType（local／server结果1／2），与 DataManager.ComflictStatus（Local0／Server1／Compare2）不同，后续实现不可混用。

LoginControl.I 为 null、必要 useInfo 或必需 UI 引用为 null 时，原路径保留异常；并没有将 null 解释为离线完成。Canvas 的 ConfirmText 则是可空显示项，空时跳过文本修改。OnUseChoose 的 handler 可空，但该方法本身已经是在消费一个选择；不能在缺少真实来源时主动调用它以解除等待。

仅这9个入口还不足以恢复冲突决定。VersionConflict、CheckSaveUserID、OnLTDataCallback 的实际数据规则，以及请求与 UI 消费闭包仍需下一批单独取证／授权。本阶段不修改这些源码或 LoginSynData；也没有将服务器空结果、失败或 SDK 缺失解释成本地胜出。运行期其他账号赋值生产者尚未穷举，已确认的是原默认初始化和原直接访问行为。

若后续需要显式 Editor 离线数据来源，应声明本地存储是本次运行的数据来源，并进入经原生证据确认的原本地选择分支；不能把服务器“不可用”伪装成“成功返回空存档”，不能以空列表+isSucceed=true调用服务器回调，也不能直接写 Finish 或 SDK 登录成功标志。本阶段没有添加该 provider。
