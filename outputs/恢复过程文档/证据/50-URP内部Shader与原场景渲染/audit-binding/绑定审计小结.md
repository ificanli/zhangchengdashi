## 官方 14.0.12 消费路径与错误对应

下面的官方路径前缀 `URP/` 为 `Library/PackageCache/com.unity.render-pipelines.universal@14.0.12/`，`Core/` 为 `Library/PackageCache/com.unity.render-pipelines.core@14.0.12/`。两包的 `package.json:4` 均为14.0.12。

- `URP/Runtime/Data/UniversalRenderPipelineAsset.cs:758`：创建 Renderers 后，将每个 UniversalRendererData 的 `shaders.coreBlitPS/coreBlitColorAndDepthPS` 直接传给 `Blitter.Initialize`。
- `URP/Runtime/UniversalRenderer.cs:178`：再次把 `data.shaders.coreBlitPS` 直接交给 `CoreUtils.CreateEngineMaterial(Shader)`，用于 Renderer 的 Blit 材质。
- `Core/Runtime/Utilities/Blitter.cs:58-61`：无条件创建 `s_Blit` 和 `s_BlitColorAndDepth`；随后 `new LocalKeyword(blitPS, "BLIT_DECODE_HDR")`。当前占位缺关键字，直接对应 Main5 第1条错误。
- `Core/Runtime/Utilities/Blitter.cs:192`：高于SM2时以指定索引调用 `cmd.DrawProcedural`。`:211-214` 的常规 BlitTexture 以 `bilinear ? 1 : 0` 选择采样 Pass。
- `URP/Runtime/Passes/CopyColorPass.cs:187-195`：`Downsampling._2xBilinear` 和 `_4xBilinear` 使用 CoreBlit 材质 pass1。当前 Pipeline 设为2x；这是与 Main5 pass1错误一致的确定静态调用来源，日志栈没有保留 C# 调用帧，故不能证明错误一定从该点发出。
- `URP/Runtime/Passes/FinalBlitPass.cs:22-23/:62-63`：按名查找 `NearestDebugDraw` / `BilinearDebugDraw`；当前占位均无命名 Pass。恢复完整官方 CoreBlit 同时满足这条契约。
- `URP/Shaders/Utils/CoreBlit.shader`：25个 Pass，`:287/:299` 声明 `#pragma multi_compile_local _ BLIT_DECODE_HDR`，`:308/:327` 声明上述 DebugDraw Pass。
- 配对的 `URP/Shaders/Utils/CoreBlitColorAndDepth.shader:19/:30` 有两个 Pass，片元入口分别 `FragColorOnly` / `FragColorAndDepth`。`Core/Runtime/Utilities/Blitter.cs:240-247` 的 `BlitColorAndDepth` API 以 `blitDepth ? 1 : 0` 选 Pass。因此配对 ColorAndDepth 占位同样不符合已安装 Blitter 契约，作为同一初始化资源对一起恢复有直接依据。

本次对 Assets、Packages 和 URP Runtime 搜索 `BlitColorAndDepth(` 没有发现调用点。**没有证据证明 Main5 执行了该 API 的 depth=true 分支**。它的恢复依据是同一次无条件初始化的配对资源与官方 API 契约。

## 同名 Shader.Find 的确定范围

工程两份导出 Shader 与官方包 CoreBlit 都使用 `Hidden/Universal/CoreBlit`；因此名称不唯一。Assets+Packages 搜索名字只命中 Shader 声明，没有直接 `Shader.Find("Hidden/Universal/CoreBlit")` 字面量调用；已确认 URP 初始化链按 Shader 字段消费。

`Core/Runtime/Utilities/CoreUtils.cs:1033-1035` 只有 string overload 调用 `Shader.Find`，而上述链匹配 `:1055` 的 Shader overload，直接 `new Material(shader)`。`ResourceReloader.cs:230-233` 仅在字段为null时重载；`:212` 的 Package.Root 分支走 `AssetDatabase.LoadAssetAtPath`。占位 Shader 非null，因此 Reload 属性不会自动把现存导出引用修正为官方 GUID。

不能靠静态资料确定任意未观测 `Shader.Find` 的实际胜出对象；需要主窗口在已有 GUI 中读回对象身份才可确认。修复两份导出、保持名字和 GUID，使这两条既有 GUID 引用都具备完整官方契约，无需依赖同名胜出顺序。
