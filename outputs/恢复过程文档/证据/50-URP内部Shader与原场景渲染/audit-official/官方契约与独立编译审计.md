## 运行契约与 Main5 两条错误

官方源根：`outputs/OccupyCityRecovered/Library/PackageCache`。`com.unity.render-pipelines.core@14.0.12/package.json` 与 `com.unity.render-pipelines.universal@14.0.12/package.json` 均明确版本 14.0.12，Unity 2022.3。

- `core@14.0.12/Runtime/Utilities/Blitter.cs:42` 的 `Initialize` 用传入的 `blitPS` 建立 s_Blit 材质；同文件 61 行**无条件**执行 `new LocalKeyword(blitPS, "BLIT_DECODE_HDR")`。因此即使尚未使用 HDR 场景，这个本地 keyword 仍是初始化契约。
- 同文件 211–228 行 `BlitTexture` / `BlitTexture2D` 通过 `bilinear ? 1 : 0` 选择 Pass；187–192 行 `DrawTriangle` 在 graphicsShaderLevel >=30 时直接 `DrawProcedural(...shaderPass...)`。Main5 的 `invalid pass index 1` 与导出原件单 Pass 直接冲突。
- 同文件 240–247 行 ColorAndDepth 通过 `blitDepth ? 1 : 0` 选择 Pass。Depth 原件同样是单 Pass，虽然 Main5 目前报的是 CoreBlit，仍属于同一真实资源契约需闭合。
- 同文件 582–600 行立方体八面体 padding 通过 LocalKeyword 控制 HDR 解码，`bilinear ? 22 : 21`，绘制后复位 keyword。
- `universal@14.0.12/Runtime/Data/UniversalRenderPipelineAsset.cs:758` 将 `universalData.shaders.coreBlitPS/coreBlitColorAndDepthPS` 传入 `Blitter.Initialize`。
- `universal@14.0.12/Runtime/UniversalRendererData.cs:108` 的 ShaderResources 字段有官方 `[Reload("Shaders/Utils/CoreBlit.shader")]` 与 ColorAndDepth 对应路径。真实序列化 GUID 命中路径应结合主 owner 的资产引用审计；仅换 shader 名称不能替代此引用分析。
- `universal@14.0.12/Runtime/Passes/FinalBlitPass.cs:22` 与 23 行的最终拷贝还通过 `FindPass` 寻找 `NearestDebugDraw`、`BilinearDebugDraw`，官方 CoreBlit 的 Pass24/23 分别提供这两个名字。

Main5 仅保留 GUIUtility 的堆栈，不能从该记录独立证明具体哪个 BlitTexture 调用者发出 Pass1；上述源码精确证明的是调用契约和导出原件的缺口。

## include 与编译适配

复用脚本：`validate_shader_fxc.py`。命令（在实际 x20 根执行）：

```powershell
& 'C:\Users\luxinyu\AppData\Local\Programs\idapromcp\source\.venv\Scripts\python.exe' -X utf8 'work/parallel-50-render/audit-official/validate_shader_fxc.py'
```

脚本只从候选抽取 Shader 内的实际 HLSL。每个 Pass 的输入为其真实 HLSLINCLUDE 加该 Pass HLSLPROGRAM；用其实际 `#pragma vertex` / `#pragma fragment` 提供 FXC `/E`。不复制业务实现，也不替换函数体。

FXC 不具备 Unity PackageManager 路径解析能力，因此脚本把 37 个可达官方 include 拷贝至 audit 目录，仅将字面 `#include "Packages/..."` 重映射到对应缓存文件的审计副本绝对路径。每个原 include 的路径和 SHA256 均在 JSON 保存；相对 include 也以原文件目录解析。源中如果有 `include_with_pragmas`，该适配器会转成标准 include（本次核心链以普通 include 为主）。缺失的主机专用 API include 原样保留，绝不创建 stub；它们在 D3D11 条件下不激活，完整路径列在 `unresolved_inactive_includes`。

实际四个宏为 `SHADER_API_D3D11=1`、`UNITY_COMPILER_HLSL=1`、`SHADER_TARGET=20`、`UNITY_VERSION=202230`，外加每次实际 stage 宏。`SHADER_TARGET=20` 对应源声明 target2.0 的预处理门；输出 profile 用 D3D11 `vs_5_0/ps_5_0`，不声称证明所有平台最低 target2.0 的能力约束。宏 UNITY_VERSION 用 2022.3 系列值而非注入游戏状态。

使用 `/Gec`：裸 FXC 对官方 Deprecated.hlsl 的全局 `half4 _DrawObjectPassData` 报 X3650，提示需要 backwards compatibility flag；该 flag 使桌面 D3D11 中 half 作为 float，未变更 HLSL 实现。FXC 对 Unity 专用 `target/editor_sync_compilation/multi_compile/vertex/fragment` pragma 发出 X3568 unknown pragma ignored，实际入口及变体由命令行显式提供；不能据此声称经过 Unity ShaderLab 前端。

覆盖：所有 CoreBlit 25 Pass、Depth 2 Pass 各自 vertex 与 fragment 基础编译；Core 每 Pass 增加 `DISABLE_TEXTURE2D_X_ARRAY`、stereo + BLIT_SINGLE_SLICE、stereo + BLIT_SINGLE_SLICE + USE_TEXTURE2D_X_AS_ARRAY；Depth 每 Pass 增加前两个分支；Pass21/22 增加 BLIT_DECODE_HDR；Pass23/24 增加 sRGB、DEBUG_DISPLAY、两者同时。最后一项 USE_TEXTURE2D_X_AS_ARRAY 是为明确激活 Blit.hlsl:109 的额外 guard 做的覆盖定义，本包的字面 include 链未声明该宏，不声称当前 Main5 实际进入 XR/single-slice 路径。

没有宣称穷举所有 HDR/debug 与 XR 关键字笛卡尔积；当前验证关闭了已知错误相关所有 Pass 与关键分支，并保留完整命令。
